# 大疆相机动作控制 MuJoCo：G1 全身跟随与关节映射

> 这是原工程的详细操作与历史验证说明。公开版总览、安装和本次发布验证以 [README.md](README.md)、[docs/GETTING_STARTED.md](docs/GETTING_STARTED.md)、[docs/VALIDATION.md](docs/VALIDATION.md) 为准。历史现场文件可能保留在本机，未随公开仓库分发。

**宇树 G1 默认使用物理迈步跟随：** 在电脑上双击 `start_unitree_g1.cmd`，再走入相机画面，**首次启动不需要按 C 或回复消息**。程序留出 8 秒就位；全身、双手和双脚可靠可见，双脚落地、直立、双臂自然下垂且稳定约 1.5 秒后，自动标定、锁定人物并响起提示音。开始跟随后可慢慢摆臂或弯膝抬脚。同侧画面抬高估计超过 3.5 厘米、膝弯曲增加超过 12°并持续至少 80 毫秒，才发出迈步请求。请求保留 **1.25 秒**，准备至少 **0.65 秒**且支撑条件满足后才进入步态；停止抬脚后等请求到期再收步。**C**重新就位标定，**N**重选人物后再按 C；**空格**暂停/继续，**R**重置仿真后重新标定，**Q / Esc**退出。人物丢失、脚腿低可信或暂停时立即取消请求，平衡控制继续运行；空间锁定不能保证多人重叠时身份不混淆。

**不用返回电脑的 G1 静止检查：** 双击 `check_unitree_g1_static.cmd` 后走入画面，自动标定后准备 3 秒，再采样 20 秒。画面上方显示中文大字倒计时；保持双脚落地、手臂自然下垂，直到看到 **“采样结束，可以活动了”**并听到结束提示音，再去操作电脑或回复消息。完成提示持续显示，重新按 C 可再做一轮。报告保存在 `artifacts/unitree_g1_handsfree_static_check.json`；采样结束表示报告已保存，仍需操作者确认采样期间是否静止、是否选中了正确的人。

**25 秒脚步复测：** 双击 **`check_unitree_g1_motion.cmd`**，走入画面并等待自动标定与 3 秒准备。采样时按提示缓慢转移重心、交替提膝；留在相机前直到持续显示 **“采样结束，可以活动了”**并响起结束提示音，再返回电脑。报告为 **`artifacts/unitree_g1_motion_check.json`**，其中 `continuous_physics` 逐物理步骤累计真实脚底高度和接触力，避免旧半秒快照漏掉短脚步。报告保存完成不等于测试通过。

默认使用 **Full 单人模式**（`--max-people 1`），保留模型的连续平滑；每帧只有一个人体候选，不能从同帧多人中挑选自己，请让其他人留在画面外。`--max-people 2` 或 `--max-people 3` 可启用多人候选选择，但静止抖动可能明显增加。人体锁定仍依靠躯干位置与大小，不能当作身份识别。

当前加入画面静止约束、防抖、异常角度拦截，以及站立、准备迈步、步态和收步之间的切换。相关部位的画面移动需至少 10 像素、由 3 个新的姿态结果确认，遮挡恢复后也重新确认；很小动作可能暂时保持。2026-10-11 的 20 秒静止记录无主体丢失、误触发或跌倒，肩、肘、腕与腰部参考无漂移，实际肘部仍有缓慢收敛。使用 `unitree_g1_walking_mapping_editor.html` 编辑映射参考，导出后替换 `unitree_g1_walking_mapping.json` 并重启；迈步时腿部由策略接管，不能直接指定左右脚相位，也不能逐帧复刻任意舞蹈、踢腿和跳跃。操作与限制见 [G1 迈步说明](G1_STEPPING_zh.md)。固定双脚跟随使用 `start_unitree_g1_physics.cmd`；全身动作映射预览使用 `start_unitree_g1_shadow.cmd`。模型有 29 个关节，手指与独立头颈未映射。

**当前验证范围：** 2026-10-12 默认入口与公共流程 **83 个核心回归用例通过**，另有 7 个 TWIST2 实验用例通过，合计 **90 个**。旧现场记录中两段进入步态却贴地的问题已通过同一输入回放复现并修复：活动速度不再被原点回拉抵消，改为约 **0.35 米/秒**前后往返，离起点前后约 **25 厘米**换向，短停保留方向与计时；惯性可能越过换向位置。

**修复后的 25 秒现场迈步复测已通过：** 12495 次逐物理步记录，两脚最高真实离地约 **1.98/1.81 厘米**且都有卸载，无跌倒、无外加身体力、无其他身体部位落地；最高倾角约 **6.13°**。人物锁定未丢失，但脚部短暂不可见仍会暂停迈步。这里确认的是该轮现场物理步态，不能宣称每次抬脚都有正确对应或能逐帧复刻任意舞蹈。报告与详细限制见 [G1 迈步说明](G1_STEPPING_zh.md)。

**新增全身跟随实验：** `start_unitree_g1_tracking.cmd` 使用 TWIST2 接收包括腿部的全身姿态参考。官方参考回放通过，但 25 秒真人相机测试曾跌倒；它保留为实验入口，不作为默认推荐，也不跟踪人的全局行走路线。操作见 [TWIST2 实验说明](G1_TRACKING_zh.md)，公开方案比较见 [其他项目调研](OTHER_PROJECTS_zh.md)。

**智元机器人已接入：** 双击 `start_agibot_x1.cmd` 可控制 MuJoCo 中的灵犀 X1 双臂，使用 `agibot_x1_mapping_editor.html` 修改对应关系。模型含 29 个旋转关节，默认四条规则控制双肩与双肘。操作与验证范围见 [智元 X1 使用说明](AGIBOT_X1_zh.md)。

本目录是独立的仿真程序。默认搭配 DJI Osmo Action 3 的 USB Webcam 模式，在 Windows 上运行；其他能够被 OpenCV 读取的摄像头也可以作为输入。

支持两种控制方式：

1. **末端跟随**：右手腕相对右肩的移动，控制机械臂末端。默认只控制画面左右、上下；`--depth` 加入单目估计的前后移动。
2. **自定义关节映射**：选择人体关键点计算角度，再按配置驱动机器人模型中指定名称的关节。

随附的机器人是简化的固定底座、三旋转关节机械臂，具有重力、关节惯性、碰撞和位置执行器。连杆启用了重力补偿，便于先验证动作控制；它不代表具体品牌机械臂的动力学。

2026-10-10 已接上真实相机完成真人动作到 MuJoCo 关节的验证。15 秒测试采集了 30 个控制状态快照，底座、肩、肘三个关节的实际角度变化范围分别约为 **67.27°、46.00°、68.14°**，对应的人体角度与目标角度也在变化。这里记录的是状态快照，不是视频帧率；整条链路的动作延迟尚未测量。

2026-10-09 在 Windows/Python 3.14 上完成的离线验证：四个末端静态目标的最大误差约 **1.40 mm**；10 秒合成轨迹的平均跟随误差约 **10.09 mm**。自定义关节测试将人体角度 `[60°, 90°, 90°]` 换算为机器人角度 `[0°, -70°, 72°]`，位置执行器正确跟随；低可信度手腕被拒绝。官方人体姿态模型已加载并处理空白图像。

配置页面通过了实际页面脚本的反向预览、导出、重复机器人关节拒绝、导入导出往返检查。当前自动浏览器访问本地预览超时，**没有完成真实浏览器布局和文件对话框验收**；双击 HTML 直接在浏览器使用无需启动本地服务器。

## 2. 安装与首次演示

打开 PowerShell，进入本目录：

```powershell
Set-Location -LiteralPath '.'
```

若本目录的独立 Python 环境已经准备好，可直接启动。另一台电脑首次使用时执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

这条命令的执行策略只作用于该次脚本进程。需要可用的 64 位 Python（当前验证环境使用 3.14）与网络。依赖装到本目录的 `.venv`，人体姿态模型下载到 `models`。

如果默认软件仓库下载很慢，可选择清华镜像安装同一套依赖：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1 -UseTsinghuaMirror
```

先运行不需要相机的演示：

```powershell
.\.venv\Scripts\python.exe teleop.py --demo
```

机械臂跟随合成的目标轨迹。空格暂停/继续，Q 或 Esc 退出。无图形演示及验证：

```powershell
.\.venv\Scripts\python.exe teleop.py --demo --headless --seconds 10
.\.venv\Scripts\python.exe validate.py
```

## 3. 相机接法与末端跟随

1. 使用支持数据传输的 USB 线连接 Action 3 和电脑。
2. 在相机上选择 **Webcam**。如果只选择文件传输，程序读不到实时画面。
3. 固定相机，尽量选择畸变较小的视角，让肩、肘、手腕始终在画面里。先在光照充足、只有一个人的场景里测试。
4. 关闭可能占用相机的会议软件、浏览器视频通话和其他相机采集程序。
5. 启动：

```powershell
.\.venv\Scripts\python.exe teleop.py --camera 0
```

摄像头编号不一定是 0；可改成 1、2。Windows 默认使用 DirectShow，如果无法打开可改为 `--backend msmf`。请求分辨率为 1280×720/30 FPS，程序会打印设备报告值；这些值仍需实际采集验证。

面对相机，摆好舒适的中立姿势，按 **C**。按键会重置仿真机械臂并标定当前手腕相对肩部的位置。

| 动作/按键 | 行为 |
|---|---|
| 手腕在原始相机画面中向右移动 | 机械臂目标沿 +Y 移动 |
| 手腕向上移动 | 机械臂目标沿 +Z 移动 |
| `--depth` 下手腕靠近相机 | 估计目标沿 +X 移动 |
| 空格 | 暂停/继续 |
| C | 重置仿真并重新标定/启用 |
| N | 重新选择前景人物；之后再按 C 标定/启用 |
| Q / Esc | 退出 |

相机窗口显示镜像，人体识别在原始画面中完成。左右手按人体解剖方向选择，`--hand left` 改用左手。

打开估计深度：

```powershell
.\.venv\Scripts\python.exe teleop.py --camera 0 --depth --scale 0.35
```

这里的三维坐标是人体姿态模型从单张 RGB 图像估计的结果，不是深度相机的测距。遮挡、转身和前后移动可能使深度抖动。默认平面模式适合先检查采集与控制。`--scale` 在平面模式中表示每个肩宽对应多少米的目标移动；深度分量表示估计人体位移到机器人位移的倍率。

## 4. 自定义人体关节 → 机器人关节

双击打开 `mapping_editor.html`，在每条规则中选择人体动作与机器人关节，调整角度范围。可以添加规则，也可以反向、设置偏置、最大速度和平滑时间。拖动预览滑块查看角度换算，导出 `joint_mapping.json`，保存到本目录并替换配置。运行中的程序不会自动读取新配置，需要重新启动。

默认规则是：

| 人体动作 | 人体角度范围 | 机器人关节 | 机器人角度范围 |
|---|---:|---|---:|
| 左肩抬臂：左髋—左肩—左肘 | 0° → 120° | `base_yaw` | -60° → 60° |
| 右肩抬臂：右髋—右肩—右肘 | 0° → 150° | `shoulder` | -10° → -110° |
| 右肘夹角：右肩—右肘—右腕 | 30° → 180° | `elbow` | 120° → 0° |

三点夹角以第二个关键点为顶点，所以手臂伸直时肘角接近 180°。将机器人角度终点设置得比起点小，即可反向映射。默认特意使用不同的人体动作驱动基座、肩、肘，展示可自定义的对应关系。

启动关节映射模式：

```powershell
.\.venv\Scripts\python.exe teleop.py --camera 0 --mapping joint_mapping.json
```

按 **C** 请求启用。如果当时还没有可靠的人体关节，窗口会显示 `START REQUESTED` 并等待；至少一条映射具备有效输入后，再重置仿真并开始跟随。关节映射使用配置里的绝对角度范围，**不会将人体当前角度自动设为零**。用配置中的 `offset_deg` 调整零位。

每条映射现在独立判断。比如髋部不在画面里，肩部映射会保持，但只要右肩、右肘、右腕可靠可见，右肘仍可控制机械臂肘关节。窗口会逐条显示 `ready` 或 `HOLD`，以及需要露出的关键点。绿色连线只说明部分身体关键点可见，不代表所有映射都已准备好。

每条规则的结构：

```json
{
  "label": "右肘弯曲 → 机器人肘关节",
  "source": {
    "type": "angle",
    "landmarks": ["right_shoulder", "right_elbow", "right_wrist"],
    "space": "world"
  },
  "robot_joint": "elbow",
  "actuator": "elbow_servo",
  "human_range_deg": [30, 180],
  "robot_range_deg": [120, 0],
  "offset_deg": 0,
  "max_speed_deg_s": 60
}
```

换算采用：`比例 = 限制到[0,1]((人体角度 - 人体起点)/(人体终点 - 人体起点))`；再由该比例在机器人起点和终点之间插值并加上偏置。结果还会受模型关节范围、执行器输入范围与速度限制约束。

高级配置还支持：

- `type: angle`：三个关键点的夹角，可定义肩、肘、髋、膝等动作。
- `type: vector_angle`：两个关键点构成向量，`axes: ["x", "y"]` 等指定投影平面；角度是 `atan2(第二轴分量, 第一轴分量)`，范围 -180° 到 180°。跨越 ±180° 时会跳变，第一版没有连续角展开，需避免跨界动作。
- `space: world`：单目模型估计的三维姿态，适合人体关节夹角。
- `space: image`：画面二维投影，考虑宽高比例，忽略估计深度；方向角只允许 x/y 轴。
- 同一个人体动作可以写成多条规则驱动不同关节；同一个机器人关节只能有一条规则，避免冲突。

肩部转动、前臂旋转与手腕姿态不能仅靠三个身体关键点完整重建。本版不提供灵巧手或夹爪开合识别。

## 5. 使用自己的机器人模型

准备 MuJoCo XML 及其引用的资源文件。先列出模型里的关节与执行器：

```powershell
.\.venv\Scripts\python.exe teleop.py --robot 'D:\robot_models\my_robot\scene.xml' --list-joints --output robot_joints.json
```

在配置页面中导入生成的 `robot_joints.json`，选择新模型的关节与执行器，导出新的映射配置，然后启动：

```powershell
.\.venv\Scripts\python.exe teleop.py --camera 0 --robot 'D:\robot_models\my_robot\scene.xml' --mapping joint_mapping.json
```

本版支持**标量旋转关节 hinge + position 位置执行器**。程序按关节和执行器名称查找，使用各自的状态地址，不要求映射顺序与模型数组顺序相同；也会考虑执行器的 gear 比例。

如果模型只有 torque/motor 力矩输入，必须先接入对应的关节控制器，本程序会明确拒绝把角度直接写入力矩输入。ball、free 和滑动关节暂不支持角度映射。机器人关节列表可以展示其他类型，但页面只提供带执行器的 hinge 关节；执行器是否确实为位置控制，由启动时检查。

固定基座机械臂最适合第一轮测试。浮动基座人形机器人即使关节映射正确，也可能因缺少平衡控制而摔倒。它的站立、行走与接触稳定性是后续控制任务。

MuJoCo Menagerie 提供 Panda、UR5e、Unitree 等模型，可作为下一步选择；要按各模型的许可证、执行器定义与控制方式接入。

## 6. 输入丢失与性能含义

- 相机读取与人体识别分开运行，各只保留最新帧/结果，不在本程序里累计旧视频。
- 输入超过 350 ms 时立即保持所有执行器指令。某条规则的关键点可信度不足时，只保持对应关节，其他有效映射继续跟随。
- 默认 Full 人体模型只检测 1 人，保留连续平滑；画面中只有一个候选，不能从同帧多人中挑选自己。标定后锁定其躯干位置与大小，人物丢失时停止人体输入，默认迈步入口立即取消迈步请求并继续平衡控制。`--max-people 2` 或 `--max-people 3` 可启用多人候选，但静止抖动可能增加。按 N 重新获取人体后需再按 C；该方式不能保证遮挡或相近位置时身份不混淆。
- 画面仍实时到达但身体被遮挡时，立即保持，识别恢复后自动继续。相机姿态结果持续过期 0.75 秒后锁定为 `CAMERA DATA STALE`，新鲜数据恢复后需要重新按 C。空格会暂停，也可以取消尚未完成的启动请求。
- 平滑与限速限制的是目标变化，不等于真实关节能立即停止；动力学仍由 MuJoCo 计算。
- 默认物理步长为 2 ms，按墙钟时间推进；CPU 卡顿时限制追赶步数，因此不保证所有电脑都能维持实时运行。
- 相机窗口的时间指标是**电脑收到帧到姿态结果完成**，不包括相机曝光、内部处理和 USB 缓冲，也不是整条链路的实际动作延迟。
- `artifacts/live_status.json` 每半秒更新控制状态、各规则的有效性及目标/实际关节角度，用于排查“人体动、机器人不动”。该诊断文件不包含相机图像。
